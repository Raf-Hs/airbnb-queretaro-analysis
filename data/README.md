# Data

Everything in this folder is derived from one public snapshot of the
**AirROI Data Portal** for Santiago de Querétaro, plus public SEPOMEX postal-code
polygons used only to label locations.

- **Snapshot / release:** `2026-07` (provider build published 2026-07-30)
- **Downloaded:** 2026-10-25
- **Geography:** `country=Mexico / state=Querétaro / city=Querétaro`
- **Licence:** CC BY-NC 4.0 (attribution, non-commercial)
- **Unit of analysis:** one Airbnb listing, plus one row per listing-month

> **Read this first — the sample is 100 listings, not the whole market.**
> AirROI's free portal exports a *representative sample* of the Querétaro market.
> The provider reports ~1,733 active listings over the trailing year; this
> download contains **100 listings**. Every number in this project describes
> that sample. Nothing here estimates total market size, total market revenue,
> or the share of the market held by any segment.

---

## 1. Why this source

The original plan was [Inside Airbnb](https://insideairbnb.com/get-the-data/),
which publishes scrape-based listing dumps with a clear methodology.

**Inside Airbnb has no Querétaro dataset.** As of 2026-10-25 its Mexico coverage
contains a single city, Mexico City. There is no Querétaro file, no "Mexico
(other)" bundle, and no state-level fallback. Substituting Mexico City,
Guadalajara, or CDMX-adjacent data would have produced a portfolio piece about a
different property market, so that option was rejected.

The alternatives considered:

| Option | Verdict |
|---|---|
| Inside Airbnb | Rejected — no Querétaro coverage at all |
| AirROI Data Portal (chosen) | Public, listing-level, includes calendar-level history, documented schema |
| Kaggle / GitHub scrapes | Rejected — undated, unlicensed, unattributable provenance |
| Scraping Airbnb directly | Rejected — violates Airbnb ToS; out of scope by design |
| Paid AirROI / AirDNA plan | Rejected — not free; would not be reproducible for a reviewer |

AirROI is a commercial STR analytics vendor that publishes free market-level
samples through its data portal. The trade-off is explicit: **better schema and
cleaner history than a raw scrape, but a 100-listing sample and no Inside Airbnb
methodology note.** That trade-off is carried through the whole analysis.

### Why the raw files are JSONL, not CSV

The provider's **CSV exports are malformed** for this market: records contain
unescaped commas and embedded quotes, so rows shift columns part-way through the
file. Loading them produces silently wrong values (prices landing in the
`host_name` column, and so on).

The JSON and JSONL exports parse cleanly and carry the same records. So:

- `listings` and `past_rates` were downloaded as **JSON** and stored as
  **JSON Lines** (one object per line, UTF-8, no BOM).
- `reviews` was downloaded as CSV because that export *does* parse cleanly
  (three columns, no free text) and was verified with `pandas.read_csv`.

Do not re-download the listings/rates CSVs and assume they match.

### External file: SEPOMEX polygons

`raw/sepomex_cp_22-qro.geojson` is a public extract of Mexican postal-code
boundaries for state 22 (Querétaro), 518 polygons, from the SEPOMEX-derived
open dataset mirrored on GitHub. It contributes exactly two things: a
`postal_code` label per listing and a sanity check that coordinates fall inside
the right polygon.

> A postal code is **not** a neighbourhood (`colonia`). CP 76000 covers a large
> slice of the historic centre; CP 76020 is a different but equally coarse area.
> Nothing in this project should be read as "the best colonia is X". See
> `docs/methodology.md` §4.

## 3. Coverage and grain

| Property | Value |
|---|---|
| Listings | 100 |
| Hosts | 50 |
| Months of calendar history | 12 (`2025-08-01` … `2026-07-01`) |
| Listing-month rows | 1,195 (99 listings × 12 + 1 listing × 7) |
| Review-month rows | 532 across 95 listings |
| Currency | MXN (provider also supplies USD at a single implied FX rate of ~19.44) |
| City-core listings used in analysis | 99 (one rural farm stay 47 km east is retained but excluded) |
| Median listing TTM revenue | MX$87,335 |
| Total TTM revenue, 99 city listings | MX$11,995,861 |
| Total TTM revenue, all 100 listings | MX$12,530,878 |

**Grain.**

- `listings.csv` — one row per listing. Performance fields are **trailing twelve
  months** (`ttm_*`), i.e. a single summary row, not a time series.
- `monthly_rates.csv` — one row per listing per month. This is the only table
  with time variation.
- `reviews_monthly.csv` — one row per listing per month where at least one
  review was left.

**Right-censoring.** July 2026 is the snapshot month. Bookings that would have
happened in May–July 2026 were partly not yet made when the data was pulled, and
reviews for those months had not been written yet (review counts fall
101 → 73 → 25 → 6 from April to July). Realised-demand claims are restricted to
**August 2025 – April 2026**. See `reports/data_quality.md` §5.

### 3.1 How the sample compares to the provider's market summary

The same AirROI market page reports full-market figures for the trailing year:

| Provider market summary | Value | This 100-listing sample |
|---|---:|---:|
| Active listings | 1,733 | 100 |
| Average nightly price | US$64 (≈ MX$1,244) | mean MX$1,303 / median MX$1,029 |
| Occupancy | 34.5% | mean 26.5% / median 24.1% (calendar) |
| Average annual revenue | US$5,577 (≈ MX$108,400) | mean MX$121,170 / median MX$87,335 |

These are **not** directly comparable and the differences are not evidence of
sampling bias:

- The provider's price and revenue are means; this analysis leads with medians.
- The provider's occupancy definition is not published. This project's calendar
  occupancy counts host-blocked nights as unearned, which mechanically lowers it.
- The sample's room-type mix (24% private rooms) may differ from the market's.

They are included so a reviewer can see the sample sits in the right order of
magnitude, not to reconcile the two.

## 5. `monthly_rates.csv` dictionary

19 columns, 1,195 rows.

| Column | Type | Notes |
|---|---|---|
| `listing_id` | int | FK to `listings` |
| `date` | date | First of month |
| `month_start` | date | Alias of `date`, used for plotting/SQL joins |
| `year`, `month` | int | |
| `month_label` | text | `Aug 2025` … `Jul 2026` |
| `quarter` | int | Calendar quarter |
| `vacant_days` | int | Nights with no reservation; includes host-blocked nights |
| `reserved_days` | int | Booked nights |
| `nights_available` | int | `reserved + vacant` = all calendar days in the month (28–31) |
| `occupancy` | float | `reserved_days / (reserved_days + vacant_days)` |
| `has_bookings` | bool | |
| `revenue_mxn` | float | Nightly-rate revenue for the month; excludes some fees (see below) |
| `adr_quoted_mxn` | float | **Quoted** ADR; non-null even in zero-booking months |
| `adr_booked_mxn` | float | **Realised** ADR; null exactly when there were no bookings (369 rows) |
| `booking_lead_time_avg` | float | Days |
| `length_of_stay_avg` | float | Nights |
| `min_nights_avg` | int | |
| `is_partial_history` | bool | True for listing `13845232`, which has only 7 of 12 months |

**Identity used in SQL:** `occupancy = reserved_days / (reserved_days + vacant_days)`.
Because `vacant_days` includes host-blocked nights, this is the same calendar
definition used at listing level. The monthly figure is a night-weighted market
aggregate (sum of reserved ÷ sum of calendar nights), so it is not directly
comparable to the median of per-listing annual occupancy. Defined in
`docs/methodology.md` §5.

## 7. Missingness

Missingness is structural and concentrated in optional metadata. No performance
field (`price_mxn`, `occupancy`, `revenue_mxn`) is missing.

| Field | Nulls / 100 | Why |
|---|---:|---|
| `instant_book` | 75 | Raw field is mostly null; **not carried forward** |
| `bedrooms` | 19 | Private-room listings often omit it (17 of 19) |
| `guests` | 19 | 18 of these 19 overlap with `bedrooms`; two listings miss only one of the pair |
| `price_per_guest_mxn` | 19 | Derived from `guests` |
| `checkout_time` | 8 | Optional |
| `checkin_time` | 7 | Optional |
| `description` | 6 | Optional |
| `photo_urls` | 6 | Optional (raw only) |
| `guest_favorite` | 6 | Optional |
| `location_is_exact` | 6 | Optional |
| `single_fee_structure` | 4 | Optional (raw only) |
| rating sub-scores | 1 each | One listing has no reviews |

**Decision:** nothing is imputed. Bedroom-based cuts explicitly show
`Unknown`/exclude the 19 rows and state the resulting `n`. Imputing bedrooms
would have manufactured the project's strongest correlation.

## 8. Known quirks a reviewer should know

1. **The sample is a sample.** 100 of ~1,733 listings. Ratios within the sample
   are meaningful; extrapolated totals are not.
2. **Quoted vs realised price.** `price_mxn` and `adr_quoted_mxn` are asking
   prices. `adr_booked_mxn` and `revenue_mxn` are realised. The two diverge: in
   April 2026 the quoted median was MX$1,150 while the booked median was
   MX$1,197.50.
3. **Revenue excludes some fees.** Total monthly `revenue_mxn` sums to
   MX$11.51M against MX$12.00M of TTM revenue (+4.3%), while reserved nights
   match exactly (9,588). The gap is consistent with cleaning and extra-guest
   fees collected outside the nightly rate. Do not describe `revenue_mxn` as
   gross booking value.
4. **Blocked days are inside available days.** `reserved + available = total`
   holds 100/100, and `blocked` overlaps `available`. Treating blocked days as
   bookable would overstate supply and understate adjusted occupancy.
5. **One partial-history listing.** `13845232` has 7 months of monthly rows, not
   12, yet its TTM fields still divide reserved nights by a fixed 365-day window
   (57 ÷ 365 = 15.6%, versus 26.9% over the 212 observed days). It is flagged
   with `is_partial_history` and retained.
6. **One rural listing.** 47 km east of the centro, a farm stay. Retained in the
   data, excluded from city statistics via `is_city_core = false`.
7. **Approximate coordinates.** 55 listings are not exact-location and 6 more are
   unknown. Distance is therefore accurate to roughly the block/colonia, not the
   building.
8. **Snapshot age.** Data is a 2026-07 build downloaded 2026-10-25, so it is ~3
   months stale and does not describe the market today.
9. **`professional_management` is 2 hosts.** Any "professional hosts earn 3.5×"
   statement is a two-host case study, not evidence of a management premium.
10. **Ratings are compressed.** Median 4.83, IQR roughly 4.74–4.89. There is very
    little signal to explain; do not read a null rating result as "quality does
    not matter".

## 10. Rebuilding from raw

```bash
# from the project root, using the project venv
python src/clean_data.py      # raw → processed/*.csv + data_quality.json
python src/build_db.py        # processed/*.csv → airbnb_queretaro.db
python src/run_queries.py     # SQL → reports/sql_results.md
python src/analyze.py         # → reports/key_metrics.json
python src/make_figures.py    # → reports/figures/*.png
```

`clean_data.py` fails loudly if a raw file is missing, if a schema assumption
breaks, or if any of its 24 checks changes state. The expected result is
**24 checks, 0 failed**.
